# Phase 9 Plan 01: `/whoami` route — static HTML+pre with .json/.txt projections — Summary

One-liner: a single ESM build script regenerates three static artifacts (`whoami/index.html`, `whoami.json`, `whoami.txt`) from `src/data/whoami.js` on every `npm run build`, giving curl users a clean text dump and browser users a terminal-style typewriter — no server required.

## What was built

Three projections of one canonical profile, generated at build time and served as static files by GitHub Pages.

### `src/data/whoami.js` (source of truth)

Exports a `whoami` object with: `name`, `role`, `employer`, `location`, `focus`, `stack` (12 items), `projects` (4 items, each `{title, oneliner, url}`), `links` (`{github, linkedin, email, resume}`), and a `generated_at` slot stamped at build time.

Content was pulled from existing canonical surfaces so voice and facts match the rest of the site — Hero (role/employer/location/focus), Skills (12 top items selected across the 6 inventory blocks), Projects + `src/work/*.md` (the four deep-dive projects).

### `scripts/build-whoami.js` (build-time generator)

ESM script (matches `"type": "module"`). Reads `src/data/whoami.js`, stamps `generated_at = today` (date only), then writes:

- `public/whoami/index.html` — `<!DOCTYPE html>` wrapper, single-line `<style>` block, `<pre id="whoami">` containing the ASCII "D" monogram (wrapped in `<span aria-hidden="true">`) and the full profile text. Followed by a ~1.25KB inline `<script>` that respects `prefers-reduced-motion: reduce` (returns immediately when set) and otherwise types the `<pre>` content back in character-by-character with a blinking cursor. The first 600 characters animate at 22ms/char; after that it switches to a chunked dump so the user isn't waiting 30 seconds. Page closes with a small footer linking back to `/`, `/#/writing`, and a `<kbd>?</kbd>` hint for keyboard shortcuts (lands later in Phase 9).
- `public/whoami.json` — `JSON.stringify(whoami, null, 2)` with a trailing newline. ASCII header is omitted (HTML-only concern).
- `public/whoami.txt` — same text body as the `<pre>`, but with the ASCII header stripped so grep/screen-reader/bot clients see clean data only.

The generator logs byte counts on success and exits 1 with `[build-whoami] FAILED: <err>` on any error, so `npm run build` halts before vite runs.

### `package.json` build wiring

`scripts.build` changed from `"vite build"` to `"node scripts/build-whoami.js && vite build"`. Every other script (`dev`, `lint`, `preview`, `deploy`) is unchanged. The GitHub Actions deploy workflow already calls `npm run build`, so no workflow changes are needed — `/whoami` ships on the next push to `main`.

### `.gitignore`

Appended at the bottom:

```

```

`public/whoami/.gitkeep` stays tracked so the directory exists on fresh clones and the generator can write into it without `mkdir`-first surprises.

## Deviations from plan

### Auto-fixed during Task 3

**1. [Rule 1 – Bug] Inline HTML head spanned 14 lines, pushing `<pre>` to line 21 — violated the must-have truth that "the profile text dominates the response body"**

- Found during: Task 3 smoke test (`curl /whoami | sed -n '1,15p'` showed only the `<style>` block, no profile text).
- Root cause: the `HTML_HEAD` template literal in `scripts/build-whoami.js` had one CSS rule per line, so 14 lines of style sat between `<!DOCTYPE html>` and `<body>`.
- Fix: collapsed the `<head>` block to a single line. `<pre>` now opens on line 4 of the response.
- Side effects: total HTML shrank 4042 → 4025 bytes, profile-text-to-wrapper ratio improved (the `<pre>` content is now clearly the dominant section of the response when viewed line-by-line).
- Commit: `01fb41f`.

No other deviations. Plan executed in the order specified.

## Decisions made (with context)

| Decision                                                                                                                                | Why                                                                                                                                                                       |
| --------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ASCII monogram is HTML-only, wrapped in `<span aria-hidden="true">`                                                                     | Per 09-CONTEXT: screen readers skip decorative art; bots and grep clients via `.txt` / `.json` get clean data.                                                            |
| `<pre>` first; `<script>` upgrades                                                                                                      | Curl, reduced-motion users, and JS-disabled browsers see the full profile on first paint. JS is pure enhancement.                                                         |
| Animation switches from per-char (22ms) to chunked (12ms × big step) after 600 chars                                                    | Full per-char animation would take ~35 seconds. Senior engineers won't wait.                                                                                              |
| `generated_at` is date-only (`YYYY-MM-DD`)                                                                                              | Keeps day-to-day diffs minimal even when the script is re-run multiple times in one day.                                                                                  |
| `scripts/build-whoami.js` is ESM (`import`, top-level `await` available)                                                                | Matches `"type": "module"` in `package.json`. No `require()` indirection, no `.mjs` rename.                                                                               |
| Generated artifacts are `.gitignored`; committed source is the JS module only                                                           | Eliminates the second source of truth and the inevitable "regenerated file changed but no source did" diff churn.                                                         |
| `<pre>` content uses `textContent` (not `innerHTML`) when the script clears + retypes it                                                | Avoids HTML re-parsing of entity-decoded ASCII characters during animation; ensures pipe characters and ANSI-free art render literally.                                   |
| Inlined `<meta name="robots" content="noindex">`                                                                                        | `/whoami` is an easter egg, not an SEO target. Robots.txt already disallows nothing, but the explicit meta tag keeps the curl-able profile out of search indexes.        |
| Footer references `<kbd>?</kbd>` shortcut                                                                                               | Forward reference to plan 09-02 (keyboard shortcuts). When that ships, the hint becomes actionable; until then it's a harmless string.                                    |
