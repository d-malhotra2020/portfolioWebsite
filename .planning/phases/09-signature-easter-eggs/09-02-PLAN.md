<objective>
Ship a keyboard-shortcut layer with a vim/GitHub-style leader-key model (`g` followed by a destination letter) plus a `?` help overlay. The hook mounts a single global keydown listener that respects existing form-input focus and modifier-key conventions, and coexists with the AgentDock's existing `Escape` handler without double-firing.

Purpose: Senior engineers expect `g a` to jump to sections. Adding this is the smallest signal that this site was built for power users, not just hiring managers.

Output: A reusable `useKeyboardShortcuts` hook, a `KeyboardShortcutsOverlay` modal, the wiring in `App.jsx`, and supporting styles in `App.css`.

Use `navigateTo('/writing')` for the `g r` binding. Note: this sets `window.location.hash = '/writing'` which the hash router translates to `#/writing` (the leading `#` is added by the browser).

From src/components/Navbar.jsx (canonical section ids):
- `home` (hero)
- `about`
- `experience` (nav label is "career")
- `projects` (nav label is "work")
- `skills` (nav label is "stack")

Navbar's smooth-scroll convention (reuse this pattern in the hook for consistency):
```js
const el = document.getElementById(href.substring(1))
if (el) window.scrollTo({ top: el.offsetTop - 100, behavior: 'smooth' })
```
The `- 100` offset accounts for the fixed statusbar + nav header.

From src/components/AgentDock.jsx (lines 126–132 — existing Escape handler):
```js
useEffect(() => {
  const onKey = (e) => {
    if (e.key === 'Escape' && open) setOpen(false)
  }
  window.addEventListener('keydown', onKey)
  return () => window.removeEventListener('keydown', onKey)
}, [open])
```
The dock only consumes Escape when `open === true`. The new shortcut layer must:
- NOT consume Escape when the overlay is closed (let the dock handle it).
- Consume Escape ONLY when the overlay is open (to close the overlay).
- The dock's handler does not call `stopPropagation`, so both handlers fire on the same event. This is fine — when the overlay opens, the dock is typically closed; when the dock is open, the overlay shouldn't be (we don't open the overlay programmatically from the dock). If both happen to be open: pressing Escape closes both — acceptable behavior, not a regression.

From src/App.jsx (mount points):
- App returns one of four route shells (writing-index, writing-post, work-post, home).
- AgentDock is mounted in ALL four shells.
- The new shortcut hook + overlay must mount in ALL four shells too (so shortcuts work on every route).
- The `g a` / `g e` / `g w` / `g s` / `g c` scroll bindings only make sense on the home route — when on other routes, they should navigate to `/#about` etc. (i.e. switch to home AND scroll to the section).

prefers-reduced-motion convention (carried from Phase 4):
- Use Framer Motion's `useReducedMotion()` hook to detect; pass to overlay component.
- When reduced: render the overlay with no enter/exit animation (or use `transition: { duration: 0 }`).

Framer Motion is already a dependency. Use `AnimatePresence` + `motion.div` for the overlay, matching the pattern in `AgentDock.jsx`.

lucide-react `Keyboard` and `X` icons are available — use them in the overlay header.

  <action>
    Create `src/hooks/useKeyboardShortcuts.js` as the single source of truth for keyboard bindings.

    Export a default function `useKeyboardShortcuts({ onToggleHelp, isHelpOpen })` that:

    1. Holds leader state in a `useRef`: `{ active: false, timeoutId: null }`. Use ref (not state) so the listener doesn't recreate on every key press.
    2. Mounts ONE `window.addEventListener('keydown', handler)` in a `useEffect` with empty deps. Removes the listener on cleanup.
    3. The handler returns early (no action) when ANY of:
       - `e.metaKey || e.ctrlKey || e.altKey` is truthy
       - The active element is `INPUT`, `TEXTAREA`, or has `[contenteditable]` set to `true` or `""`. Check via `document.activeElement?.tagName` and `document.activeElement?.isContentEditable`.
    4. If leader is NOT active:
       - On `e.key === 'g'` (case-insensitive — check `e.key.toLowerCase() === 'g'`): set `leader.active = true`, clear any existing timeout, set a new timeout (1500ms) that resets `leader.active = false`. Call `e.preventDefault()`. Return.
       - On `e.key === '?'` (this fires on Shift+/ across layouts): call `onToggleHelp()`, `e.preventDefault()`. Return.
       - On `e.key === 'Escape'` AND `isHelpOpen`: call `onToggleHelp()` to close it. Do NOT `e.preventDefault()` (let the dock's handler also see it if it cares; the dock only acts when open).
       - Otherwise: do nothing (let the key through).
    5. If leader IS active:
       - Clear the leader-expire timeout immediately.
       - Set `leader.active = false`.
       - Match `e.key.toLowerCase()` against the binding table:
         - `'a'` → scroll to `#about`
         - `'e'` → scroll to `#experience`
         - `'w'` → scroll to `#projects`
         - `'s'` → scroll to `#skills`
         - `'c'` → scroll to `#contact`
         - `'r'` → `navigateTo('/writing')`
         - anything else → noop (leader silently consumed)
       - For the scroll bindings: if `document.getElementById(targetId)` exists (we're on the home route), use the same smooth-scroll pattern as Navbar (`window.scrollTo({ top: el.offsetTop - 100, behavior: 'smooth' })`). If the element doesn't exist (we're on a writing/work route), call `navigateTo('/')` first, then on the next tick scroll to the section: `setTimeout(() => { const el = document.getElementById(targetId); if (el) window.scrollTo({ top: el.offsetTop - 100, behavior: 'smooth' }) }, 50)`. The hash router updates synchronously on `navigateTo`; the 50ms gives React one render cycle to mount the home layout.
       - For all matched bindings: call `e.preventDefault()`.
    6. Cleanup also clears any pending leader timeout (no memory leak).

    Do NOT export a binding table from this hook. The overlay component (Task 2) needs to list the same bindings; rather than duplicating, export a SECOND named export `SHORTCUTS` — an array of `{ keys: string[], action: string, hint: string }` objects:

    ]
