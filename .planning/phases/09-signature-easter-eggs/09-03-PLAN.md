  <action>
    Edit src/components/AgentDock.jsx with focused edits. Do NOT rewrite the whole file.

    Edit 1 — module-level constants and helpers. Above the AgentDock component (after the existing GREETING constant, around line 16), add: a STORAGE_KEY constant equal to the string `drew-agent-dock:v1`; a DEFAULT_MESSAGES constant equal to the single-element greeting array; a `loadPersistedMessages` function that reads STORAGE_KEY from window.sessionStorage, JSON-parses it, validates the result is a non-empty array of objects each with string `role` and string `content`, and returns DEFAULT_MESSAGES on any failure (parse error, schema mismatch, null, empty array, missing window). Wrap the whole read in try/catch so SSR-style environments or storage-disabled browsers fall through to DEFAULT_MESSAGES; a `persistMessages(messages)` function that calls `window.sessionStorage.setItem(STORAGE_KEY, JSON.stringify(messages))` inside a try/catch, with the catch body left intentionally empty (Safari private mode degrades silently).

    Both helpers live at module scope (NOT inside the component) so they do not recreate on every render.

    Edit 2 — lazy initializer. Replace the existing messages useState (line 109-111) with `const [messages, setMessages] = useState(loadPersistedMessages)`. Pass the FUNCTION reference, NOT a call. React invokes it once on mount.

    Edit 3 — persistence effect. Add a NEW useEffect, placed AFTER the existing input-focus effect (around line 124) and BEFORE the existing Escape-key effect (around line 126). The new effect depends on `[messages]`. Body: if `messages.length === 1` AND `messages[0]?.content === GREETING`, call `window.sessionStorage.removeItem(STORAGE_KEY)` inside a try/catch and return early; otherwise call `persistMessages(messages)`.

    Why the early-return: this keeps storage clean after `clearChat()` until the user actually sends a message. Without it, the clear-button handler would set messages to DEFAULT_MESSAGES, the effect would fire and immediately re-persist the greeting array, and `sessionStorage.getItem('drew-agent-dock:v1')` would return a non-null string — violating the orchestrator's acceptance criterion.

    Edit 4 — clearChat handler. Inside the component, ABOVE the existing `send` function (around line 134), add a `clearChat` arrow function that: calls `window.sessionStorage.removeItem(STORAGE_KEY)` inside a try/catch; calls `setMessages(DEFAULT_MESSAGES)`; calls `setShowSuggest(true)`. Order matters: remove the key BEFORE the setState, so even if the persistence effect re-writes on the next render, the gate in Edit 3 catches it.

    Edit 5 — leave the existing Escape handler at lines 126-132 unchanged. This plan does NOT touch the keyboard layer; that is plan 09-02's responsibility, and the orchestrator's acceptance criterion explicitly says no double-handling.

    Edit 6 — keep the showSuggest initializer as `useState(true)`. If a recruiter reloads mid-conversation, the render guard (`messages.length === 1`) already hides the chips. No change needed.
  </action>
